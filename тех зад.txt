ТЕХНИЧЕСКОЕ ЗАДАНИЕ: TASK MANAGEMENT API
1. Общее описание
Цель: Разработка безопасного REST API для управления задачами с системой аутентификации и авторизации, поддержкой командной работы и расширенными возможностями поиска и фильтрации.

Бизнес-контекст: Система позволяет пользователям создавать, организовывать и отслеживать задачи в персональном и командном пространствах.

2. Функциональные требования
2.1. Управление пользователями
Регистрация с валидацией email

Аутентификация по email/password с JWT

Профиль пользователя: имя, avatar, настройки уведомлений

Восстановление пароля через email

2.2. Управление задачами
java
// Статусы задачи

3.2. Модель данных
sql
-- Пользователи
CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    password VARCHAR(255) NOT NULL,
    first_name VARCHAR(100),
    last_name VARCHAR(100),
    avatar_url TEXT,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- Рабочие пространства
CREATE TABLE workspaces (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    description TEXT,
    owner_id BIGINT REFERENCES users(id),
    created_at TIMESTAMP DEFAULT NOW()
);

-- Задачи
CREATE TABLE tasks (
    id BIGSERIAL PRIMARY KEY,
    title VARCHAR(500) NOT NULL,
    description TEXT,
    status VARCHAR(50) DEFAULT 'TODO',
    priority VARCHAR(50) DEFAULT 'MEDIUM',
    due_date TIMESTAMP,
    workspace_id BIGINT REFERENCES workspaces(id),
    author_id BIGINT REFERENCES users(id),
    assignee_id BIGINT REFERENCES users(id),
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- Индексы для оптимизации
CREATE INDEX idx_tasks_status ON tasks(status);
CREATE INDEX idx_tasks_workspace_id ON tasks(workspace_id);
CREATE INDEX idx_tasks_due_date ON tasks(due_date);
CREATE INDEX idx_tasks_assignee_id ON tasks(assignee_id);

5. Оптимизация производительности
5.1. Проблемные места для оптимизации:
sql
-- Медленный запрос (ДО оптимизации):
SELECT * FROM tasks 
WHERE workspace_id = ? 
AND status IN ('TODO', 'IN_PROGRESS') 
AND assignee_id = ?
ORDER BY created_at DESC;

-- Оптимизированный запрос (ПОСЛЕ):
SELECT t.id, t.title, t.status, t.priority, 
       u.first_name as assignee_name,
       COUNT(*) OVER() as total_count
FROM tasks t
LEFT JOIN users u ON t.assignee_id = u.id
WHERE t.workspace_id = ? 
AND t.status IN ('TODO', 'IN_PROGRESS') 
AND t.assignee_id = ?
ORDER BY t.created_at DESC
LIMIT 20 OFFSET 0;
5.2. Стратегии оптимизации:
Индексы: Составные индексы для частых запросов

Пагинация: Page-based и cursor-based пагинация

Кэширование: Redis для часто запрашиваемых данных

N+1 проблемы: Решение через JOIN FETCH в Hibernate

Проекции: Использование DTO вместо Entity
